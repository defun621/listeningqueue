## 第一轮：分解与审查

```text
可靠收听
├─ M0：从来源到声音
│  ├─ 读取：有限时间、有限体积
│  ├─ 识别：身份、文字、媒体地址
│  ├─ 选择：发现与入队分开
│  └─ 播放：媒体地址交给浏览器
├─ M1：保存用户意图
│  ├─ 身份：重复发现仍是同一节目
│  ├─ 队列：保存手动顺序
│  ├─ 进度：独立于队列成员关系
│  ├─ 删除：保留已见记录
│  └─ 写入：成功提交，失败回滚
└─ M2：持续发现
   ├─ 到期：时间、间隔、启用状态
   ├─ 拉取：同源互斥，异源独立
   ├─ 提交：内容与来源状态一起保存
   └─ 停止：等待已启动的工作
```

以下分类说明依据，不表示可信度排序。
“约定”包含明确的产品选择。
约定仍然必须遵守。

| 部件 | 分类 | 依据与待验证点 |
| --- | --- | --- |
| M0 读取 | 推断＋约定 | 等待必须有界；15 秒和 4 MiB 是当前取值 |
| M0 识别 | 事实＋推断 | 相同文字有不同编码；身份不能随编码变化 |
| M0 选择 | 约定 | 已验收的行为要求手动入队；唯一队列由规格规定 |
| M0 播放 | 推断 | 有媒体地址仍不足以证明能听见 |
| M1 身份 | 约定＋推断 | 使用来源与外部 ID；重复拉取不应复制节目 |
| M1 队列 | 约定 | 用户顺序具有权威性 |
| M1 进度 | 约定 | 移出队列不能抹除播放进度 |
| M1 删除 | 推断 | 上游可能继续返回已删除节目；需要独立已见状态 |
| M1 写入 | 推断＋约定 | 部分写入会破坏一致性；SQLite 是既定选择 |
| M2 到期 | 约定 | 固定间隔；最小 60 秒；网页默认一小时 |
| M2 拉取 | 推断＋约定 | 慢源不能影响其他源；同源禁止重叠 |
| M2 提交 | 推断 | 先推进来源状态，可能跳过未保存内容 |
| M2 停止 | 推断 | 工作未结束就关闭数据库，会造成失败 |

线程、证据卡和整数队列位置都是实现选择。
它们本身不证明用户目标成立。

## 第一轮：方案与实验

先固定预期结果，再改变一个条件。
所有新增实验使用本地数据与临时数据库。
原有测试作为基线，共 54 项通过。

### E1：文字与身份

假设：等价 XML 表达应产生相同文字和身份。
方案：在解析边界恢复字符，再构造节目。
不在数据库或网页中修补残缺文字。

| 组别 | 输入 | 修复前 | 修复后 |
| --- | --- | --- | --- |
| A | 直接写中文，使用 `&amp;` | 通过 | 通过 |
| B | 十进制字符引用 | 中文丢失 | 通过 |
| C | 十六进制字符引用 | 中文丢失 | 通过 |

预期标题和简介：`中文 A & B`。
预期身份：`episode-中`。
失败时标题实际为 `A & B`。
对应场景：`SC-POD-018`。

学习：读取 XML 不等于保留全部文字。
底层解析器将数字引用表示为整数。
原来的文字函数忽略了这些整数。
修复只增加字符转换。

### E2：保存与恢复

假设：失败不会留下部分节目更新。
方案：保留整个来源拉取的事务边界。
比较成功、节目编码失败、来源状态编码失败。

初始队列为 B、A。
A 的进度为 37.5 秒。
后续拉取更新 A，并加入 C。

| 组别 | 条件 | 观察 |
| --- | --- | --- |
| A | 全部写入成功 | 重启后重试新增零项 |
| B | C 无法编码 | A 的更新也回滚；重试新增一项 |
| C | 来源状态无法编码 | 节目与已见写入回滚；重试新增一项 |

三组最终均有三个节目。
队列仍为 B、A。
播放进度仍为 37.5 秒。
对应场景：`SC-DB-016`。

另测删除后重启，再拉取变化后的标题。
结果：节目仍被删除，已见记录保留。
对应场景：`SC-DB-017`。

学习：M1 的状态边界通过本轮实验。
目前没有证据要求重写持久化层。
这些实验不代表所有数据库故障均已覆盖。

### E3：来源是否独立

假设：线程并发足以保证来源独立。
对照方案：每批全部完成后，再检查到期来源。
候选方案：检查到期与等待完成分开。

A 在时间 60 到期。
B 在时间 120 到期。
只改变 A 是否持续阻塞。

| 组别 | 条件 | 修复前 | 修复后 |
| --- | --- | --- | --- |
| A | A 被释放 | B 正常开始 | B 正常开始 |
| B | A 持续阻塞 | B 未能开始 | B 独立开始 |

对应场景：`SC-SUB-014`。
旧测试只覆盖同时到期。
它没有覆盖后来到期的来源。

学习：并发启动不代表持续独立。
原运行循环等待整批完成，形成跨批阻塞。
修复后，轮询继续运行。
同源仍由原来的互斥机制保护。

## 第二轮：根据发现继续分解

```text
识别
├─ 原始编码
└─ 恢复后的文字与身份

调度独立性
├─ 同时到期
├─ 后来到期
└─ 退出时仍有未完成工作
```

无需继续拆成通用调度框架。
新增的状态只是本次运行拥有的拉取任务。

初版 E3 使用短轮询间隔复现问题。
第二轮改用手动事件触发轮询。
新增接口前，实验报告不支持 `#:poll-evt`。
加入接口后，两组都通过。
注入时钟决定到期时间。
线程等待上限仅用于发现死锁。

补充退出实验：先请求停止，再释放拉取。
结果：停止等待拉取，成功状态随后保存。
对应场景：`SC-SUB-015`。

学习：取消批次等待后，退出仍须等待自己启动的工作。
现有 RSS 网络边界保留 15 秒超时。
注入的无限阻塞扩展仍可能拖延退出。

## 证据范围与未决事项

- M0 的可听见结果仍需人工确认。
- M1、M2 图片是程序生成的状态证据卡。
- 这些图片不是浏览器截图，也不证明真实网络可用。
- M1 有进度存储接口；网页还没有进度上报与恢复。
- 完整纯队列操作尚未实现；当前只提供部分操作。
- 当前网页没有完整的播放失败提示。
- 混合有效与无效节目时，解析器会静默跳过无效项。
- 后两项与 SP-01 的错误说明存在差距，需要后续明确处理。
- SP-03 的目标描述使用“admit”，实现决定却要求手动入队。
- 后续默认自动入队，与已验收的手动选择仍需明确衔接。
- 本轮不改变以上产品选择，也不宣称完整 v0.1 已满足。

数字引用修复可能恢复以前丢失的 GUID 字符。
已有数据库可能保存过残缺身份。
本轮不猜测身份对应关系，也不自动合并历史节目。
若旧数据受影响，需要单独核查。
